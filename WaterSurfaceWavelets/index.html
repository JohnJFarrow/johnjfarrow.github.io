UL Water Surface Wavelets

January 22, 2026

Thoughts about implementing Water Surface Wavelets.

There are various implementations on the web:

Original Repo in CPP, no compute shaders

SleepyTaco

LoganDooley

Water Surface Wavelets Unity

The original repo has a limited version of the original code used in the paper - it uses C++ to do the simulation calculations and shaders to do the rendering, whereas the original paper describes an implementation where the simulation calculations were done in a shader (perhaps a compute shader).

Other implementations don't build or don't work, mostly because they are too old to be built with 2026 tools.

Target​

Ideally we can construct an implementation where:

  • the simulation is done in a compute shader in Niagara
  • the simulation results are written to render textures
  • an Unreal material is used to read the render textures and render the ocean surface
  • the algorithm supports collision and wave reflection from stationary objects (land) and moving objects (boats) to ideally this could be implemented as well
  • if possible a C++ implementation could be used where buoyancy data is needed

Basic Approach​

Similar to this FFT Waves Example we have:

  • a plane mesh object (1,025 x 1,025 vertices = 1,050,625 vertices)
  • a Niagara simulation
  • a set of render targets which holds vertex and pixel data written to by the Niagara simulation. These are much lower resolution that the plane mesh (say 256 x 256)
  • a material set on the plane mesh which accesses the render targets and calculates vertical and horizontal displacement at each of the mesh vertices
