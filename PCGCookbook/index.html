PCG Volume​

A PCG volume is dropped into the map to implement procedural generation. It contains two components:

  • a BrushComponent which defines the bounds of the volume and, by default, the generation
  • a PCG component, which contains a PCG Graph which contains the rules by which elements will be generated

Points​

A point is the most basic element used by PCG. The properties of a point are defined in the FPCGPoint struct in PCGPoint.h.

PCG nodes samples surfaces such as meshes or landscapes to generate points.

Here is an example graph which samples a surface to calculate positions of a set of points and then spawns meshes (of trees) at those points:

The Surface Sampler node samples whatever surface is connected to its Surface input pin. Broadly speaking, the World Ray Hit Query node could be replaced with a Get Landscape Data node and the sampled points would be the same.

Conceptually, the Surface Sampler gets the bounds of the graph and from those bounds calculates a 2d grid of points, and then evaluates the World Ray Hit Query node at each of these points.

The World Ray Hit Query node projects a set of rays downwards from the top of the PCG volume till they collide with something such as a landscape.

This results in one point for each grid point, with the x,y values coming from the grid postions and the z value being wherever the projected ray intersects the landscape.

The properties of points are defined on the FPCGPoint structure and cannot be added to or deleted, but attributes can be added to points and removed from them.

Number of points​

The Surface Sampler has several setting which determine the number of points:

  • Points Per Squared Meter - how many points will be generated
  • Point Extents - the size of the points
  • Looseness - how much space between points

The scale of a PCG volume is in meters. Setting the scale to 10x10x10 will make an area of 100m meters. It is not obvious how these settings interact.
Consider a PCG volume which as Scale=(10,10,10), so 100m squared. With Points Per Squared Meter = 1, and Point Extents = (100,100,100) each point is 1m square so we get 100 points in the 100m area of the volume like this:

If we increase the Points Per Squared Meter to 2, nothing changes because the Point Extends limit the maximum possible points to 100.

If we decrease the Points Per Squared Meter to 0.5, nothing changes. Testing smaller values it is not to till we reduce Points Per Squared Meter to 0.2 that we see any change, when the number of points drops from 100 to 81.

If we increase the Points Extents to (100,100,100), we change from 100 to 50 points as that is the maximum that will fit in the 10m x 10m area.

If we decrease the Points Extents to (50,100,100), we change from 100 to 200 points as that is the maximum that will fit in the 10m x 10m area.

In this scenario when the maximum number of points is filling the available area, changing the looseness up or down has no effect.

From Discord, "Cell size is Extents2(1 + looseness)" and there is a random chance of a point in each cell.

Looking at the code, a grid is created with a cell count. This is determined from (at least) the extents, so in the above case the extents (100,100,100) create a grid with 100 cells, so this is the maximum number of points regardless of the Points Per Squared Meter.

If the extents are reduced to (10,10,100) the cell count is 420, and with a Points Per Squared Meter of 1, this generates 385 points. With the option Keep Zero Density Points ticked this generates 420 points.

Looking at the code in PCGSurfaceSampler.cpp the cell size is calculated like this:

const FVector::FReal SquaredUnitsPerPoint = (100.0 * 100.0) / Params.PointsPerSquaredMeter;
// Compute approximate cell size based on the point extents relative size.
// Knowing that X * Y = SQM
// if X = aY, then aY * Y = SQM -> aY^2 = SQM -> Y = sqrt(SQM / a)
const FVector::FReal MinCellSize = 2.0 * FMath::Min(Params.PointExtents.X, Params.PointExtents.Y);
const FVector::FReal MaxCellSize = 2.0 * FMath::Max(Params.PointExtents.X, Params.PointExtents.Y);
const FVector::FReal BaseCellSize = FMath::Sqrt(SquaredUnitsPerPoint / (MaxCellSize / MinCellSize));

CellSize = FVector(
    BaseCellSize * 2.0 * (Params.PointExtents.X / MinCellSize),
    BaseCellSize * 2.0 * (Params.PointExtents.Y / MinCellSize),
    2.0 * Params.PointExtents.Z);

Graph Evaluation​

Each PCG graph node consists of these major parts:

  • the node itself, such as
  • a Settings object, such as UPCGSurfaceSamplerSettings which derives from UPCGSettings and defines pins and holds properties for that node type. The intention of separating the node itself from the settings is that the settings object can be populated with values which will then be used as the node is created.
  • the Element such as FPCGSurfaceSamplerElement which is the function which actually performs whatever the node does

A PCG graph is evaluated by the FPCGGraphExecutor::ExecuteScheduling() method. This evaluates nodes in the graph in a series of phases, including EPCGExecutionPhase::PrepareData, EPCGExecutionPhase::Execute, and EPCGExecutionPhase::PostExecute.

An element implements the IPCGElement interface and has methods corresponding to the execution phases, for example the method FPCGSurfaceSamplerElement:::PrepareDataInternal() method is called on a Surface Sampler node during the PrepareData execution phase.

Seeds​

PCG is deterministic, a PCG volume graph has a seed and regenerating the content will produce the same content for the same seed. Changing the seed will change the generated content.

A PCG graph also has a seed, so the same graph can be used in multiple places; if the seeds are different the generated content will be different.

World Ray Hit Query does not hit all meshes​

By default the World Ray Hit Query node uses the WorldStatic collision channel. A Sphere placed on a map has Collision Presets = Default so will block the WorldStatic channel, but (for example) the Floor object on a new level has Collision Presets = BlockAllDynamic so the floor not block the WorldStatic channel. If the channel is not blocked no rays will hit the floor so no points will be generated.

If the meshes you want to hit are spawned by a Static Mesh Spawner then each mesh in Mesh Entries needs to have it Collision Presets set to BlockAllDynamic or whatever corresponds to the collision channel used by the World Ray Hit Query node. The Static Mesh Spawner defaults to NoCollision which will not work.

Level Streaming / Partitioning​

By default all meshes created by a Static Mesh spawner in a PCG volume are loaded when the game is started. There is no streaming. All the instances are part of the same actor under the same component.

Use the Is Partitioned property on the PCG component to activate streaming.

With unpartitioned PCG graph the static meshes which are spawned are owned/held by the PCG Volume:

whereas if Is Partitioned = true, the meshes are owned/held by PCG Partition Actors which are owned/held by the PCG World Actor:

PCG Partition Actors are created in a grid. The grid size is a controlled by the Partition Grid Size property on the PCG World Actor. It defaults to 256 meters

Unused PCG Partition Actors are automatically tidied up, to force this manually use the Tools | PCG Framework | Delete | Unused Partition Grid Actors.

If the map is large enough (~ 2km) and the PCG volume covers the entire map, when you press play in the editor distance grids will not be rendered. To create level of detail representations for these grids use Build | Build HLODS; this might take several minutes to build.

There is a potential problem with nodes which reference the actor, such as Get Actor Data. If the PCG volume is not partitioned then there is 1 actor. If the PCG volume is partitioned, there is 1 actor for each PCG Partition Actors. So a graph which references 'Self', for example, makes its own points with a Create Points Grid node and then copies those points onto the target Actor using a Copy Points node will create the points for every single PCG Partition Actor node.

This is fixed by either:

  • using Actor Filter = Original instead of Self on the Get Actor Data node
  • using Coordinate Space = Original Component on the Create Points Grid node

GPU​

Docs Using PCG with GPU Processing

Youtube: Unreal Engine 5.6 PCG - Ep 9 - Introduction to GPU

Using the Static Mesh Spawner as an example, the Execute on GPU property controls if the GPU is used for generation.

If the GPU is not used, then instanced static meshes are used, where the CPU holds 1 copy of the mesh and 1 transform for each instance of that mesh. These transforms are held in main memory and uploaded to the GPU for rendering (each frame or each draw call or when they change?). This enables the mesh and transforms to be used for things other than rendering, such as physics, collisions, and navigation.

If the GPU is used the transforms are held in the GPU and only a lightweight reference:

This means they cannot be used for non-rendering functions such as physics, collisions and navigation. The instance data is resident on the GPU only, it is not saved and is lost when the map is reloaded.

So GPU generation is most suited to runtime spawning of non-interactable elements with no collisions such as grass.

GPU spawning performance better than CPU, and the more instances the greater the difference

Types of blueprint node​

Execute with context: This is the main function that gets executed from the input pin of your custom node. This is where you grab your inputs and decide what you're gonna do to them save them to a variable, do simple operations, etc.

Point loops: a few types of multithreaded functions where you describe the logic you're doing per-dataset.

Single point loop: one point in, one point out. This is the most commonly used loop type, typically you'd use it to execute logic based on the single points properties or attributes (i.e. changing its size based on its density)

Pair point loop: two points in, one point out. I typically use this to compare two datasets (i.e If you want to find the distance to a point in another dataset). It seems to have two point inputs, so if you have two equally sized datasets, I'm assuming it's going to give you points with the same index, but I've not had to use it yet, so can't say for sure

Multipoint Loop: one point in, many points out. This is for when you want to create new points. (i.e. spawning randomly spread points around the input point)

Iteration loop: this is where anything goes, really. Two full datasets in, one dataset out. Here you can specify logic based on the size of the datasets (i.e. if you need to compare points of a large dataset to the points of a smaller one), or you can transfer attributes from a smaller dataset to a larger one (or vice versa), without copying ove the points themselves.
