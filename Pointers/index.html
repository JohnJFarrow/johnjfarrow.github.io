UL Unreal Garbage Collection and C++ Pointers

November 17, 2025

This article lists the different types of Unreal pointers and their usages. In Unreal there is a distinction between pointers intended for use with UObject derived classes and non-UObject derived classes. Objects derived from UObject are garbage collected, that is they are managed by tracking references to them, and when there are no non-weak references they are marked for destruction and deletion at a later time.

Non UObject based objects are managed using reference-counting pointers, and when their reference could drops to zero they are immediately deleted.

UObject Pointers​

TypeDescriptionLifecycle
UObject*Raw UObject ptrGC if UPROPERTY()
TObjectPtr<>replaces Raw object ptrGC if UPROPERTY()
TWeakObjectPtr<>Weak reference
TStrongObjectPtr<>Strong referenceCG

Raw UObject Pointer​

Declared like this:

UObject* RawPtr;

This is a normal C++ pointer. Does nothing special.

When declared with UPROPERTY() it will participate in garbage collection and keep the referenced object from being garbage collected.

UPROPERTY()
UObject* RawPtr;

Raw pointers should not be used, it is better to use TObjectPtr<> because TObjectPtr<> initializes the pointer to null. In some circumstances a raw pointer not get initialized to null, for example if it is a member of struct and the struct is allocated on the stack.

TObjectPtr<>​

Use this instead of raw pointers.

In engine code TObjectPtr is used for member variables:

UPROPERTY(Category=Sprite, EditAnywhere)
TObjectPtr<UPaperSprite> Sprite;

It is also used in maps, parameters and variables but usually only when these elements end up referencing values stored in TObjectPtr-based member variables.

TMap<TObjectPtr<USceneComponent>, EControlRigComponentMapDirection> MappedComponents;

void ULocomotionAnalysisProperties::InitializeFromCache(TObjectPtr<UCachedAnalysisProperties> Cache)

TObjectPtr<UMassStateTreeProcessor>& ExistingProcessor =
    RequirementsHashToProcessor.FindOrAddByHash(DependenciesHash, DependenciesHash);

TObjectPtr<> is different in editor builds. Instead of storing a pointer, it might store an index in the object handle table which describes a referenced object that hasn't been loaded yet.

TObjectPtr<> participates in garbage collection in the same way as a raw pointer does - it only effects garbage collection if it is a UPROPERTY()

TWeakObjectPtr<>​

This maintains a weak reference to an object, meaning it does not prevent garbage collection, so the referenced object might be null or invalid.

Usage patterns from engine code​

  • use the Pin() method to get a strong pointer:
void Method(TWeakObjectPtr< UObject > WeakPtr)
{
    TStrongObjectPtr<UObject> StrongPtr = WeakPtr.Pin();
    if (StrongPtr)
    {
        // use the strong ptr 
    }
}

The Get() method of TWeakObjectPtr<> returns a raw pointer, so does not prevent the object being garbage collected immediately afterwards.

The Pin() method of TWeakObjectPtr<> returns a TStrongObjectPtr<> which does prevent the objects being garbage collected immediately afterwards.

TStrongObjectPtr<>​

This is a pointer preventing the object from being garbage collected. This is useful for preventing garbage collection when an object is not already held by a UPROPERTY TObjectPtr<> (which would already prevent garbage collection).

Usage patterns from engine code​

  • preventing an object being garbage collected for a defined scope:
if (TStrongObjectPtr<UControlRig> ControlRig = Pairs.Key.Pin())
{
    for (const AControlRigShapeActor* ShapeActor : Pairs.Value)
    {
        if (ShapeActor->IsSelected())
        {
            return true;
        }
    }
}

Non-UObject Pointers​

The pointers are similar to standard template libary pointers like std::shared_ptr. They provide reference-counted (as opposed to garbage collected) pointers for non-Uobject items. These cannot be used for UObject based objects.

TypeDescriptionLifecycle
TSharedPtr<>Ref count
TSharedRef<>Ref count
TWeakPtr<>Ref count
TUniquePtr<>Owns

TSharedPtr<>​

This is the Unreal equivalent of an std::shared_ptr and uses reference counting. This can be constructed from a new object (using MakeShared), or an existing c++ pointer (using MakeShareable). It cannot be used to point to UObject derived classes.

An existing object can hand out shared pointers to itself using MakeSharedFromThis() if the object derives from TSharedFromThis.

TSharedPtr can be made threadsafe at the cost of being a little slower.

Epic recommends using TSharedRef instead whenever possible as TSharedRef cannot be null.

Read the comments in Engine\Source\Runtime\Core\Public\Templates\SharedPointer.h for more information.

TSharedRef<>​

This is a version of TSharedPtr which does not allow the pointer to be null.

It cannot be used to point to UObject derived classes.

Read the comments in Engine\Source\Runtime\Core\Public\Templates\SharedPointer.h for more information.

TWeakPtr<>​

Like TWeakObjectPtr this holds a reference to an object but does not prevent it being deleted.

Use the Pin() method to get a TSharedPtr<> which will prevent the object being deleted until the TSharedPtr<> is deleted.

If the object has in fact been deleted before you call Pin(), you will still get a TSharedPtr<> but it will be null, so always check the TSharedPtr before dereferencing it. Even if you call IsValid() on the TWeakPtr<> and then call Pin(), the object might have been deleted between those calls so you still need to check the TSharedPtr<>.

TUniquePtr<>​

This holds the only reference to an object, and it cannot be shared with other pointers. Typically used to indicate ownership. Constucted like this:

TUniquePtr<UE::Tasks::FPipe> Pipe = MakeUnique<UE::Tasks::FPipe>(*FString::Printf(TEXT("SimPipe:%d"), Index));

Asset Pointers​

TSoftObjectPtr<>​

This is a type of weak pointer to a UObject, that also keeps track of the path to the object on disk. That object might or might not be currently in memory.

It is used to specify assets that you may want to asynchronously load on demand.

The IsNull() method on the pointer checks if it could ever be loaded i.e. does it have a valid path.

The IsValid() method on the pointer checks if it is loaded.

If it can be loaded (IsNull()==false) and is not loaded (IsValid()==false) then you can call the LoadSynchronous() method to load it immediately.

If it can be loaded (IsNull()==false) and is not loaded (IsValid()==false) you can load it asynchronously using a worker thread.

Assuming some member declared like this:

public:
    UPROPERTY(VisibleAnywhere, BlueprintReadWrite )
    TSoftObjectPtr< UStaticMesh > TestStaticMesh;
    // and a shared ptr to hold the mesh after we loaded it
    TSharedPtr< FStreamableHandle > TestMeshHandle;

In a method such as BeginPlay you can asynchronously load the asset (in this case a mesh) like this:

void ANyetCharacter::BeginPlay()
{
    Super::BeginPlay();

	if (!TestStaticMesh.IsNull() && !TestStaticMesh.IsValid() )
	{
		FStreamableManager& Manager = UAssetManager::GetStreamableManager();

		const FSoftObjectPath& Path = TestStaticMesh.ToSoftObjectPath();

		TestMeshHandle = Manager.RequestAsyncLoad(
			Path,
			FStreamableDelegate::CreateWeakLambda(this, [this,Path]()
				{
					if (TestStaticMesh.IsValid())
					{
						UE_LOG(LogTemp, Log, TEXT("async loaded %s"), *Path.ToString())
					}
					else
					{
						UE_LOG(LogTemp, Log, TEXT("async load failed %s"), *Path.ToString());
					}
				}));
	}
}

Use IsValid()​

Testing a pointer to a UObject by comparing it to null is not enough because Unreal has garbage collection and an object might exist but be in a non-usable state because it has been marked for destruction or is midway though being destroyed.

The IsValid function checks the pointer is not null and checks it for garbage collection flags:

UE_FORCEINLINE_HINT bool IsValid(const UObject *Test)
{
	return Test && FInternalUObjectBaseUtilityIsValidFlagsChecker::CheckObjectValidBasedOnItsFlags(Test);
}

struct FInternalUObjectBaseUtilityIsValidFlagsChecker
{
	inline static bool CheckObjectValidBasedOnItsFlags(const UObject* Test)
	{
		// Here we don't really check if the flags match but if the end result is the same
		checkSlow(GUObjectArray.IndexToObject(Test->InternalIndex)->HasAnyFlags(EInternalObjectFlags::Garbage) == Test->HasAnyFlags(RF_MirroredGarbage));
		return !Test->HasAnyFlags(RF_MirroredGarbage);
	}
};
